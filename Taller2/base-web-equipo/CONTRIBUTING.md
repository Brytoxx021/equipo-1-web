# CONTRIBUTING.md — Equipo Hispania

¡Gracias por colaborar con nuestro proyecto! Esta web está desarrollada con HTML y CSS y presenta al equipo y su proyecto.

## 1. Cómo contribuir

- Revisa los issues abiertos y elige uno.
- Comenta si vas a trabajar en él para evitar duplicar esfuerzos.
- Crea una rama nueva para tus cambios.
- Comprueba que todo funciona antes de enviar tu contribución.

## 2. Nombres de ramas

Utiliza minúsculas, sin espacios ni tildes, y separa las palabras con guiones.

- `feature/nombre-mejora`: nuevas funcionalidades.
- `fix/nombre-error`: correcciones.
- `docs/nombre-documentacion`: documentación.
- `style/nombre-estilo`: cambios visuales o CSS.

Ejemplos:
- `feature/fichas-miembros`
- `fix/imagen-gatos`
- `docs/actualizar-contributing`

## 3. Mensajes de commit

Utiliza el formato:

`tipo: descripción breve`

Tipos permitidos:

- `feat`: nueva funcionalidad.
- `fix`: corrección de errores.
- `docs`: documentación.
- `style`: cambios visuales.

Ejemplos:
- `feat: añadir fichas de miembros`
- `fix: mejorar texto alternativo de la imagen`
- `docs: actualizar instrucciones`

## 4. Pull Requests (PR)

Todas las Pull Requests deben seguir la plantilla `pull_request_template.md` incluida en el proyecto.

Completa sus apartados:

- **Qué cambia:** explica brevemente las modificaciones.
- **Por qué:** indica el problema que resuelve o la tarea que completa.
- **Cómo comprobarlo:** describe los pasos para verificar los cambios.
- **Closes #:** añade el número del issue relacionado, por ejemplo, `Closes #3`.

Antes de enviar la PR, comprueba que los cambios funcionan correctamente y que solo incluyen modificaciones relacionadas con la tarea.

## 5. Buenas prácticas

- Mantén el código ordenado y legible.
- Respeta la estructura de archivos del proyecto.
- Utiliza HTML semántico y textos alternativos descriptivos.
- Realiza cambios pequeños relacionados con el issue.
- Respeta las contribuciones de los demás.

¡Gracias por ayudar a mejorar Equipo Hispania!
